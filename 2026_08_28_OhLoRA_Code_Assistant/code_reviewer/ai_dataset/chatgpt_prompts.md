## 1. 기본 원칙

* 데이터셋 생성 시 **hard 하게 분류하면, 특정 cutoff 기준으로 결과가 완전히 달라지므로,** 이러한 결과로 인해 모델 학습 혼동 가능
* 따라서 **확률 기반의 soft 분류** 를 이용하여, 모델이 **보다 유연하게 확률 예측** 가능하게 함

## 2. 프롬프트 템플릿

### 2-1. code string 에 대한 확률 예측

```
- 목적
  - {목적 설명}

- 데이터셋 형식
  - 파일 이름: dataset_{이름 입력}.csv
  - 컬럼 형식:
    {'code' (string) : 목적에서 언급한 분류 기준에 해당하거나 해당하지 않는 code snippet,
     'probability' (float) : 해당 code snippet이 목적에서 언급한 분류 기준에 부합할 확률 (0.0 - 1.0 사이의 값),
     'prob_human_validation' (float) : 데이터셋에 대한 인간 검증 결과를 위한 컬럼으로 비워 둠,
     'final_ground_truth' (float) : probability 컬럼 값과 인간 검증 결과를 이용한 최종 ground truth 값을 위한 컬럼으로 비워 둠}

- 데이터셋 규모
  - 2,000 개 row 로 구성

- 유의 사항
  - 코드가 목적에서 언급한 분류 기준에 부합하지 않음이 명확하면 확률값 (probability) = 0.0 이다.
  - 코드가 목적에서 언급한 분류 기준에 부합함이 명확하면 확률값 (probability) = 1.0 이다.
  - 이 데이터셋을 딥러닝 모델이 원활하게 학습할 수 있도록, probability의 비중을 고르게 한다.
    즉, 확률이 0.0인 데이터가 20%, 1.0인 데이터가 20%로 하고,
    나머지 60%의 데이터의 경우 특정 확률 구간에 쏠리지 않고 0.05 - 0.95 사이의 확률 값에 고르게 분포하게 한다.
  - 2,000 개 row의 정렬 순서 (생성 순서) 는 probability 에 대한 오름차순 (확률 0.0 에서 1.0 으로 올라가는 순서) 이다.
  - 데이터셋의 code snippet의 형태는 최대한 다양하게 하여, 딥러닝 모델이 최대한 다양한 케이스를 학습하여 unseen data가 들어오는 실제 환경에서 성능을 발휘할 수 있게 한다.

위 목적과 데이터셋 형식에 따라 csv 파일을 생성해서, 다운로드 링크를 반드시 포함해서 반환해 줘.
```

## 2-2. code string 에 대한 유사도 비교

* 두 code snippet 간 의미가 서로 반대인 경우는 오히려 문맥상 유사도가 높다고 봐야 할 수 있으므로, 유사도 구간에 **음수는 포함하지 않고 0.0 ~ +1.0 으로 한다.**

```
- 목적
  - {목적 설명}

- 데이터셋 형식
  - 파일 이름: dataset_{이름 입력}.csv
  - 컬럼 형식:
    {'code_1' (string) : 목적에 따라 유사도를 비교할 1번째 code snippet,
     'code_2' (string) : 목적에 따라 유사도를 비교할 2번째 code snippet,
     'similarity' (float) : 해당 두 code snippet 간 유사도
                            (코사인 유사도 개념, 이론상 -1.0 ~ +1.0 사이의 값이지만 데이터셋 생성 시 실질적으로는 0.0 ~ +1.0 사이의 값),
     'sim_human_validation' (float) : 데이터셋에 대한 인간 검증 결과를 위한 컬럼으로 비워 둠,
     'final_ground_truth' (float) : similarity 컬럼 값과 인간 검증 결과를 이용한 최종 ground truth 값을 위한 컬럼으로 비워 둠}

- 데이터셋 규모
  - 2,000 개 row 로 구성

- 유의 사항
  - 목적을 고려했을 때의 두 code snippet 간 유사도가 서로 매우 높음이 명확하면 유사도 (similarity) = +1.0 이다.
  - 목적을 고려했을 때, 두 code snippet 간 상관 없음이 명확하면 유사도 (similarity) = 0.0 이다.
  - 이 데이터셋을 딥러닝 모델이 원활하게 학습할 수 있도록, 음수 구간은 제외한 후 similarity (유사도) 의 비중을 고르게 한다.
    즉, 유사도가 0.0인 데이터가 20%, +1.0인 데이터가 10%로 하고,
    나머지 70%의 데이터의 경우 특정 유사도 구간에 쏠리지 않고 +0.05 ~ +0.95 사이의 유사도 값에 고르게 분포하게 한다.
  - 2,000 개 row의 정렬 순서 (생성 순서) 는 similarity 에 대한 오름차순 (유사도 0.0 에서 +1.0 으로 올라가는 순서) 이다.
  - 데이터셋의 code snippet의 형태는 최대한 다양하게 하여, 딥러닝 모델이 최대한 다양한 케이스를 학습하여 unseen data가 들어오는 실제 환경에서 성능을 발휘할 수 있게 한다.

위 목적과 데이터셋 형식에 따라 csv 파일을 생성해서, 다운로드 링크를 반드시 포함해서 반환해 줘.
```

### 3-1. 목적 설명 (불필요 print 제거)

```
  - Python 코드에는 핵심 결과를 보고서 형태로 출력하는 등 유용한 print 나 logging 도 있지만, 디버깅 용으로 출력해서 프로덕션 코드에서는 삭제해야 하는 불필요한 print, logging 등도 있다.
  - 생성 대상 (각 데이터 row는 2줄 이상이 아닌, 반드시 1줄로 한다.)
    - logger 를 사용하는 형태 : logger.warning(...), logger.error(...), logger.info(...), logger.debug(...), logger.critical(...) 형태의 1줄
    - print 를 사용하는 형태 : print(...) 형태의 1줄
  - logger.debug(...), 디버깅용 변수를 print 하는 것 (예: print(a) 등) 는 불필요한 logging 으로 간주한다.
  - 반면, 핵심적인 진행 상황 로깅 등도 있다.
  - 분류 기준은 "불필요한 print, logging" 이다.
```
