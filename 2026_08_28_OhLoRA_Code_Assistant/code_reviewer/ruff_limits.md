## 1. `ruff` 소개

**ruff** [(GitHub)](https://github.com/astral-sh/ruff) 는 **Rust 언어로 쓰인, 매우 빠른 Python linter (규칙 검사기)** 이다.

* [900개 이상의 코드 규칙](https://docs.astral.sh/ruff/rules/) 존재
* `pip install ruff` 를 이용한 간단한 설치 가능
* 본인 사용 버전: `ruff==0.16.6`

## 2. `ruff` 의 한계점

[전체 53개 규칙 (AI 기반 규칙 11개, 정적 분석 43개)](code_review_standard.md) 에 대해 **`ruff` 의 대체 가능한 규칙이 있는지 테스트** 한 결과, 다음과 같은 한계점이 발견되었다.

* 대체 가능한 정적 분석 규칙의 개수 자체가 **적음 (43개 정적 분석 규칙 중 12개)**
* 일부 정적 분석 규칙 적용에 한계가 있음 (`false negative (미탐)` 의 존재 등) → 이로 인해 대체 불가
* 일부 정적 분석 규칙에 대해 불친절한 설명 → 대체 난이도 높음

### 2-3. 불친절한 설명

일부 정적 분석 규칙에 대해서는 **설명이 불친절** 한데, 해당 부분을 `ruff` 로 대체할 수 있지만 **대체 난이도가 타 규칙에 비해 비교적 높다** 고 판단됨.

| 정적 분석 규칙                                       | `Oh-LoRA` 규칙 번호<br>(함수 이름)            | `ruff` 규칙 번호 | `ruff` 의 오류 검사 패턴                                                                                          |
|------------------------------------------------|---------------------------------------|--------------|------------------------------------------------------------------------------------------------------------|
| 리스트 컴프리헨션 사용이 가능한 경우, 리스트 컴프리헨션 사용             | `03_check_suggest_list_comprehension` | `PERF401`    | - 출력 결과의 line 번호 오류<br>- 해당 line 자체를 텍스트로 출력하지도 않음                                                         |
| `import` 순서 (표준 라이브러리 > 서드파티 라이브러리 > 로컬) 준수 여부 | `01_library_orders`                   | `I001`       | line 번호가 아닌 **각 파일 자체** 에 대해, 다음과 같이 **구체적이지 않은 설명** 만 출력<br>- `Import block is un-sorted or un-formatted` |

## 3. `ruff` 의 정적 분석 규칙 대체에 한계가 있는 이유

* 디테일한 코드 포맷 규칙 (regex 로 추출할 만한) 을 **정확히 만족** 시키는 ruff 규칙의 부재
* 빈 파일, `README.md` 등 특정 파일의 유무와 같이 **코드 외적** 으로 검사하는 규칙의 부재

### 3-1. 이 한계점이 시사하는 것

* 기업, 팀, 개인 등 Python 개발자가 **코드 리뷰의 명확한 기준** 을 디테일하게 정립하기 위해서는, `ruff` 만으로는 부족할 수 있음
